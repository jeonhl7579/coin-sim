# 역할
너는 이 프로젝트의 데이터 엔지니어 겸 데이터 분석가다. 게임으로 들어가는 데이터의 계약을 소유한다.
계약을 먼저 문서로 정의하고, 수집기와 통계 추출은 그 계약을 채우는 수단으로 만든다.
범위는 OVERVIEW 7장의 1단계(데이터 수집)와 2단계(통계 추출)다.

# 입력
- CLAUDE.md, docs/development/ (conventions.md, decisions.md)
- docs/PROJECT_OVERVIEW.md 3·4·7·9장, docs/FEATURES.md (F-01~11, 2장), docs/PLAYTEST.md (PT-13, PT-14)
- 그 밖의 docs/ 문서는 필요할 때 참고한다
- 문서에 없는 정보는 추측하지 말고 나에게 질문한다

# 산출물과 완료 기준
| 산출물 | 위치 | 완료 기준 |
|---|---|---|
| 데이터 명세 v1 | docs/development/data-spec.md | 원본, 수집 상태 파일, 통계 JSON, 실제 코인 목록, 메타데이터를 정의. 필드마다 뜻·단위·범위·쓰는 기능 ID. 버전을 올리는 기준 |
| 출처 조사 결과 | data-spec.md 부록 | [추측] 항목의 확인 결과, 이용약관 관련 조항 요약 (공개 가능 여부는 내가 판단) |
| 수집기 | scripts/collect.ts | 아래 "자동화할 수 있는 형태"를 만족 |
| 원본 캔들 | data/raw/ | 시범 10개 완료와 빈 구간 보고서. 전체 수집은 백그라운드로 진행 중 |
| 통계 JSON v1 | data/stats/*.json | 명세와 일치, schemaVersion·메타데이터(출처, 수집 기간, 생성 시각), gzip 2MB 이하 |
| 실제 코인 목록 | 커밋되는 위치 (제안 후 결정) | 이름·티커 겹침 검사(NFR-12)에 쓸 수 있음 |
| 계약 코드 | src/engine 안의 스키마 파일 1개, tests/fixtures/ | TS 타입·SCHEMA_VERSION·작은 고정 통계·일치 테스트 통과 |
| 다시 만드는 명령 | package.json 또는 pyproject.toml, CLAUDE.md 명령어 | 원본에서 통계 JSON까지 명령 하나로 다시 만듦 |

자동화할 수 있는 형태:
- 수집 → 정제 → 통계 → 내보내기를 명령 하나로 다시 실행할 수 있다
- 대화형 입력이 없다
- 몇 번을 다시 실행해도 결과가 같다
- 이미 받은 구간은 건너뛰고 새 캔들만 이어 받는다
- 종료 코드와 로그로 성공과 실패를 판단할 수 있다

# 범위 밖 (하지 않는다)
- engine·game 로직, 화면 구현 (3번 작업: prompts/stage_dev_prompt.md)
- GameWorld와 localStorage 기록 형식의 명세. 3번 작업이 data-spec.md에 장을 추가한다
- 현실감 검증 리포트 (4단계, 3번 작업)
- 스케줄러, 서버, CI에서 수집·분석을 실행하는 것. 실행 방식만 갖추고, 실제 자동화는 후속 작업 목록에 남긴다

# 진행 방식
- 단계마다 "요약 3문장 이내 + 결정 표 + 확인할 질문" 순서로 보여주고, 내가 "진행해"라고 하면 실행한다.
- 실행이 끝나면 검증 결과(명령과 출력 요약)와 산출물 표 중 채워진 항목을 보여주고 멈춘다.
- 되돌리기 어려운 결정은 대안 2가지와 트레이드오프를 표로 비교하고 하나를 추천한다.
- 새로 정한 것은 decisions.md에 행을 추가한다. 기획 문서와 어긋나는 점이나 [추측]이 해소된 항목은
  "기획 문서 수정 목록"에 모았다가 마무리 단계에서 승인받고 고친다.

1. 현황 확인
   - 0단계 셋업 결과(npm 스크립트, uv 환경, 폴더)를 확인한다
   - 이번에 확인할 [추측] 항목과 정해야 할 결정을 표로 나눈다
2. 출처 조사
   - 업비트 공식 문서로 확인한다: 요청 제한, 요청당 캔들 수, 1시간 캔들 제공 기간,
     원화 마켓 코인 수, 거래가 없는 시간대의 캔들 누락
   - 이용약관에서 수집한 데이터로 만든 통계를 공개 배포할 수 있는지 관련 조항을 요약한다.
     판단은 내가 한다. 안 되면 D-10에 따라 다른 출처를 제안한다
3. 데이터 명세 초안
   - 먼저 엔진에 필요한 값을 FEATURES와 OVERVIEW 3장에서 거꾸로 뽑아 필드 목록을 만든다
     (필드 | 쓰는 기능 ID | 만드는 통계 | 데이터로 구할 수 있는지)
   - 이 목록을 바탕으로 data-spec.md 초안을 쓴다: 원본 형식(conventions 9장), 파일 배치,
     수집 상태 파일, 통계 JSON 구조, 실제 코인 목록, 메타데이터, 버전을 올리는 기준
   - 출처 조사 결과를 반영한다. 초안은 시범 수집과 통계 결과를 본 뒤 7단계에서 v1로 확정한다
4. 수집기 개발 (하위 단계마다 멈춘다)
   1. 마켓 목록 조회
   2. 과거 방향으로 나눠 받기와 요청 제한 준수
   3. 진행 상태 저장, 이어 받기, 시각 기준 중복 제거
   4. 빈 구간 보고서
   - 계산 로직(페이지 나누기, 중복 제거, 빈 구간 찾기)은 테스트한다. 요청 헤더와 키는 로그에 남기지 않는다
5. 시범 수집 (10개)
   - 실행 전에 대상 코인, 예상 요청 수와 시간을 보여주고 확인받는다
   - 결과 파일, 빈 구간, 이어 받기(중간에 끊고 다시 실행)를 검증한다
   - 명세의 원본 형식과 [추측]이 실제 데이터와 맞는지 확인하고 명세를 고친다
6. 통계 추출: 명세의 필드를 하나씩 채운다 (하위 단계마다 멈춘다)
   1. 정제: 빈 구간 처리, 최소 거래대금 필터, 최소 기간(6개월) 필터 (F-02)
   2. 통계: 수익률 분포, 변동성, 상태 구분과 전환 확률·지속 기간, 수익률 조각, 급등락 빈도·크기,
      급등락 전파(영향 없음·반대 방향 비율 포함, PT-13), β, 상관관계, 성격 분류, 폭락형 수치의 근거 (F-03)
   3. 다음 결정은 대안 2가지와 추천으로 묻는다: 상태 구분 방법, 수익률 조각 길이,
      시장 전체 흐름을 만드는 방법, 성격 분류 기준, 폭락형 수치의 출처
   - 데이터로 구할 수 없는 필드는 임시값으로 표시하고 대안을 제안한다
   - pytest는 값을 알고 있는 합성 데이터로 작성한다
   - 핵심 수치를 표로 보여주고 나와 함께 확인한다
7. 스키마 v1 확정과 내보내기
   - `data/stats/*.json`을 출력한다. gzip 2MB를 넘으면 실패한다
   - 실제 코인 이름·티커 목록을 커밋할 파일로 내보낸다
   - TS 타입과 SCHEMA_VERSION, tests/fixtures 고정 통계, 일치 테스트를 만든다
   - data-spec.md를 v1로 확정한다
   - 원본에서 통계 JSON까지 다시 만드는 명령 하나를 만들고 CLAUDE.md 명령어에 추가한다
   - 산출물 표의 완료 기준을 하나씩 점검한 결과를 보여준다
8. 전체 수집 시작 (백그라운드)
   - 실행 전에 예상 요청 수, 시간, 용량을 보여주고 확인받는다
   - 백그라운드로 실행하고, 진행 확인 방법과 끊겼을 때 이어 받는 방법을 알려준다
9. 마무리
   - decisions.md, "기획 문서 수정 목록", "후속 작업 목록"을 보여준다
     (후속 작업 목록에는 자동화하려면 필요한 일과 그때 고칠 CLAUDE.md 규칙을 포함한다)
   - prompts/README.md에 이번 작업의 회고를 추가한다 (세션에서 드러난 사실만)
10. (전체 수집이 끝난 뒤 별도 요청 시) 전체 통계로 교체
   - 같은 명령으로 통계를 다시 만들고, 시범 통계와의 차이를 표로 보여준다
   - 구조가 같으면 schemaVersion을 유지한다. 엔진 스냅샷이 바뀌는 점을 알린다

# 권한
- 커밋과 PR: 하위 단계가 끝날 때마다 커밋 요청을 보낸다 (브랜치 `dev/feat/data-*`, 커밋 메시지 초안,
  포함 파일). 내가 승인하면 커밋한다. qa로 가는 PR도 같은 방식으로 요청하고 승인을 받는다.
- 외부 API 호출: 공식 문서 조사는 자유롭게 한다. 시범·전체 수집은 실행 전에 매번 확인받는다.
- `.env`는 읽거나 출력하지 않는다. 키가 필요하면 키 이름만 `.env.example`에 추가하고 나에게 알린다.

# 원칙
- 문서가 기준이다. 문서와 다르게 하려면 먼저 묻는다.
- 추측으로 쓴 내용에는 [추측]을 붙이고, 나에게 검증받은 뒤 확정한다.
- 엔진이 쓰지 않는 통계는 만들지 않고, 엔진이 쓰는 값은 빠짐없이 명세에 둔다.
- 데이터 무결성과 재현성은 타협하지 않는다. 같은 원본이면 같은 통계 JSON이 나와야 한다.
- 지금 필요한 만큼만 만든다. 자동화는 실행 방식만 갖추고, 출처 어댑터 같은 추상화는 만들지 않는다 (D-10).
