# Coin Sim — 프로젝트 개요

> 실제 코인 시세 데이터에서 통계를 추출해 **가상의 코인과 시세를 생성**하고,
> 그 위에서 혼자 플레이하는 **코인 매매 시뮬레이터 게임**을 만든다.

- 작성일: 2026-11-10
- 상태: 기획 완료 (구현 시작 전)
- 상세 기획: [REQUIREMENTS.md](REQUIREMENTS.md) → [FEATURES.md](FEATURES.md) → [PROCESS.md](PROCESS.md) → [SCREENS.md](SCREENS.md)
- 표기 규칙: **[추측]** = 확인되지 않은 사실. 구현 전에 확인한다. / **[임시값]** = 제안한 임시 수치. / **[테스트 후 결정]** = 개발·테스트해 보고 정할 항목 ([PLAYTEST.md](PLAYTEST.md)에 모음)

### 해결할 문제 (우선순위 순)
1. 내 페이스에 맞춰 즐길 수 있는, 긴장감 있는 게임이 필요하다
2. 매매를 해 보고 싶지만 돈을 잃는 건 부담스럽다
3. 급등락 상황에서 판단해 볼 기회가 없다

### 핵심 가치
1. **게임의 재미** 우선: 이벤트 빈도, 연출, 보상은 재미를 기준으로 조정한다.
2. **현실감**은 일부만 양보: 이벤트가 없는 구간의 시세 통계는 실제 시세와
   비슷한 범위에 있어야 하며, 개발 단계에서 분석 리포트로 확인하고 README에 공개한다.
   (게임 안에는 검증 화면을 두지 않는다)

### 범위에서 제외 (다음 프로젝트로 넘김)
- 서버를 통한 실시간 세션 연결 (WebSocket)
- 멀티플레이, 랭킹, 데일리 챌린지 → 실서비스로 전환할 때 1순위 후보
- 로그인, 서버 DB

> 시세를 받는 인터페이스(`feed`)를 하나로 통일해 두고,
> 다음 프로젝트에서 이 부분을 서버 WebSocket 방식으로 바꿀 수 있게 설계한다.

## 2. 게임 컨셉

### 한 줄 요약
실제 코인의 "성격"을 학습해 만든 **가상 코인 10개**를 예산 안에서 자유롭게 사고팔고,
시장을 흔드는 **이벤트가 발생하면 선택지를 골라** 대응하는 시뮬레이터 게임.

### 진행 방식: 혼합형
- **기본은 자유 매매**: 차트가 재생되는 동안 사용자가 언제든 매수·매도한다.
- **이벤트 시점에는 선택지**: 급등락, 급상승, 또는 보유하지 않은 코인에서 발생했지만 시장 전반에 큰 영향을 주는 이벤트가 생기면, 재생을 일시정지하고 뉴스와 선택지를 보여준다.

### 플레이 흐름
```
게임 시작 → 로딩 (통계 불러오기, 코인 10개와 시세 생성)
     → 준비 상태 (일시정지): 과거 차트와 코인 소개를 보고 첫 매수
     → [재생] → 차트 재생 + 자유 매매
     → (이벤트) 일시정지 → 뉴스 + 선택지 → 재생 재개
     → ... 반복 ...
     → 종료 (또는 중도 종료) → 결과 화면 (수익률, 비교 지표, 등급. 업적은 MVP 이후)
```
- 준비 상태에서는 시세가 흐르지 않는다. 시장가는 과거 구간의 마지막 종가로 체결되고, 지정가도 걸 수 있다.
- 상세 흐름과 예외 처리는 [PROCESS.md](PROCESS.md) 참고.

### 게임 규칙

> **기준 문서:** 확정값은 이 표가 기준이다. 요약이 있는 곳: [REQUIREMENTS.md](REQUIREMENTS.md) 1장, 이 문서 8장. 수정은 여기서 먼저.

### 주문 처리 방식

> 기준: [FEATURES.md](FEATURES.md) 2장 "주문". 수정은 기준 문서에서 먼저.

| 구분 | 의미 | 게임에서의 체결 |
|---|---|---|
| 시장가 | 지금 시장 가격으로 바로 체결 | 현재가로 즉시 체결. 슬리피지 없음 |
| 지정가 | 정한 가격에 도달하면 체결 | 매수는 가격이 지정가 이하로, 매도는 지정가 이상으로 가면 체결. 세부 단계 가격마다 판정하고 그 세부 단계 가격에 체결 (지정가를 건너뛰면 건너뛴 가격) |

- 코인은 소수점 단위로 매매할 수 있다. 최소 주문 금액은 5,000원.
- 지정가 매수를 걸면 주문 금액과 수수료만큼 현금을 묶어 둔다. 체결 가격은 판정한 세부 단계 가격(지정가와 같거나 유리)이고, 더 낮게 체결되면 남은 묶인 현금을 돌려준다.
- 금액은 원 단위 정수. 수수료는 올림, 매도로 받는 금액은 내림 (플레이어에게 불리한 쪽).
- 지정가 주문은 취소할 수 있고, 취소하지 않으면 판이 끝날 때까지 유지된다.
- 공매도와 레버리지는 없다.

### 이벤트 시스템

| 영향 범위 | 예시 | 효과 |
|---|---|---|
| 시장 전체 | 대형 거래소 파산, 규제 발표 | 10개 코인이 함께 급등락 (코인별 민감도에 비례) |
| 섹터 | 밈코인 열풍 | 같은 섹터 코인만. **2차로 미룸** |
| 개별 코인 | 해킹, 대형 파트너십 | 해당 코인. 이벤트마다 다른 코인으로 퍼질지 판정 (아래 전파 규칙) |

**전파 규칙**

> 기준: [FEATURES.md](FEATURES.md) 2장 "이벤트 전파". 수정은 기준 문서에서 먼저.

- 이벤트가 생길 때 전파 여부·세기·범위를 시드 난수로 판정한다.
  - 전파 확률: 충격이 발생한 코인의 성격(대장 높음 ~ 소형·밈 낮음)과 이벤트 종류(해킹·거래 정지는 높음, 파트너십·상장은 낮음)로 결정
  - 받는 코인 충격 = 원래 충격 × 전파 세기 × 받는 코인의 β
  - 전파 범위: 전부 / 일부 코인 / 없음
  - 전파 결과: 전파 대상이 되어도 영향이 없을 수 있고, 반대 방향으로 움직일 수도 있다 (별도 확률)
- 전파 시점: 같은 캔들에 바로 전파되거나, 1~3캔들 늦게 전파될 수 있다.
- 전파 여부는 뉴스 문구로 **힌트만** 준다 (명시하지 않음). 전파 대상 코인의 결과는 후속 기사로 알린다.

**선택지와 체결 가격**

> 기준: [FEATURES.md](FEATURES.md) 2장 "선택지와 체결 가격", 모달 동작은 [SCREENS.md](SCREENS.md) S-04a. 수정은 기준 문서에서 먼저.

- 선택지를 띄우는 조건: 보유 코인이 충격을 받거나 실제로 전파를 받을 때, 또는 시장 전체 이벤트일 때
- 일시정지 시점의 가격 (선택지로 낸 주문의 체결 가격)
  - 충격이 처음 발생한 코인: 충격이 **절반 반영된** 가격
  - 충격이 전파되는 다른 코인: 충격이 **반영되기 전** 가격
  - 시장 전체 이벤트: 모든 코인을 충격이 처음 발생한 코인으로 보고 절반 반영 **[테스트 후 결정]**
- 진행: 선택 → 주문 체결 → 남은 충격 반영 (즉시 전파 대상 코인의 결과 포함) → 재생 재개
- 선택지 예시: 보유 코인 전량 매도 / 절반 매도 / 그대로 보유 / 현금 30%로 추가 매수 / 직접 주문
- 모달이 떠 있는 동안은 일시정지 상태이고, 선택지를 골라야 재개된다. 직접 주문은 모달 안에서 한다 (상세: [SCREENS.md](SCREENS.md) S-04a)

**뉴스**
- 뉴스 문구: 템플릿 조합으로 자동 생성 (실제 뉴스 기사는 쓰지 않음)
- 선택지를 띄우지 않는 이벤트(보유하지 않은 코인에서 전파 없이 끝나는 이벤트 등)는 멈추지 않고 화면의 뉴스 피드에 기사로 흘려 보여준다.

## 3. 가상 시세 생성

### 생성 방식: A + B 혼합

| 방식 | 역할 |
|---|---|
| **B. 통계 모델** (뼈대) | 시장을 상승장 / 하락장 / 횡보장 상태로 나누고 상태가 확률적으로 바뀜. 각 상태의 변동성과 지속 기간은 실제 데이터에서 추출 |
| **A. 실제 데이터 변형** (세부) | 현재 상태에 맞는 실제 수익률 조각을 무작위로 뽑아 붙여 현실적인 잔진동을 만듦 |
| **이벤트** | 급등락을 추가로 넣고 뉴스 문구를 생성 |

### 코인 간 연관성
코인 10개가 각자 따로 움직이지 않고 시장 흐름을 함께 타도록 만든다.

```
코인 수익률 = 민감도(β) × 시장 전체 흐름 + (섹터 흐름) + 그 코인만의 움직임
```
- 섹터 흐름은 2차로 미룬다. 1차에서는 0으로 두되, 공식에 들어갈 자리는 남겨 둔다.

### 가상 코인 생성기
- 이름, 티커, 소개문: 무작위 조합
- 성격 타입별 수치 (예: 대장 / 대형 / 중형 / 소형·밈코인 / 폭락형)
- 10개 코인 구성: **확정** 고정 비율 (대장 1, 대형 2, 중형 3, 소형·밈 4) + 숨은 폭락형 0~1개
  - 판마다 높은 확률로 폭락형 1개를 넣는다. 넣을 때는 소형·밈 한 자리 또는 중형 한 자리를 폭락형으로 바꾼다. 폭락형이 없는 판도 있다.
  - 폭락형이 나올 확률과 소형·밈·중형 중 어느 자리를 바꿀지의 비율은 임시값 **[테스트 후 결정]** (PT-14)
  - 폭락형은 플레이어에게 공개하지 않는다. 로딩 카드, 차트 헤더, 결과 화면 모두 원래 자리의 성격(소형·밈 또는 중형)으로 표시한다.

### 시드 기반 생성
- 시드를 지정할 수 있는 난수 함수(mulberry32 등)를 사용한다. `Math.random()`은 시드를 지정할 수 없어서 쓰지 않는다.
- **시드 + 통계 JSON = 항상 같은 차트**. 테스트와 재현에 사용한다.

### 캔들 1개를 만드는 순서
1. 상태 결정: 현재 상태 유지 또는 전환 (B)
2. 기본 수익률: 상태에 맞는 실제 수익률 조각에서 뽑기 (A)
3. 시장 흐름과 민감도 반영
4. 이벤트 발생 여부 판정 → 발생하면 급등락 추가, 전파 여부·범위·시점·결과 판정, 뉴스 생성. 앞 캔들에서 늦게 전파되도록 예약된 충격도 여기서 반영
5. 가격 계산: 이전 종가 × (1 + 수익률)
6. 캔들 구성: 세부 움직임으로 시가·고가·저가·종가를 정하고(고가·저가는 세부 단계 가격의 최대·최소), 거래량은 변동 폭에 비례

### 실행 위치: 브라우저
- 게임 시작 시 캔들 600개(× 코인 10개)를 한 번에 메모리에 생성하고, 게임 시계에 맞춰 한 칸씩 보여준다.
- 미래 데이터가 브라우저 메모리에 있지만 혼자 하는 게임이라 문제가 없다.

### 현실감 검증
실제 코인과 가상 코인의 통계를 나란히 비교하는 **개발용 리포트**를 만든다 (포트폴리오 핵심 자료, README에 게시).
게임 화면에는 넣지 않는다. 플레이어에게는 필요 없는 정보이기 때문이다 (2026-11-17 결정).
- 변동성, 수익률 분포 (급등락이 얼마나 자주 나오는지), 최대 낙폭, 코인 간 상관관계
- 참고할 실제 시세의 특징: 급등락이 정규분포 예상보다 자주 일어나고, 변동이 큰 구간이 몰려서 나타나며, 수익률 자체는 예측하기 어렵다.

## 4. 데이터 파이프라인

```
[업비트 캔들 API] → collect.ts → data/raw/ → analysis/ (Python) → data/stats/*.json → [게임]
```

### 수집 (TypeScript)
- 대상: 업비트 원화(KRW) 마켓에 지금 상장된 코인 전체, 1시간 캔들, 받을 수 있는 전체 기간 (**확정**)
- 확장 방식: 통계를 뽑다가 데이터가 부족한 점이 생기면 그때 수집 범위를 늘린다
- 상장 폐지된 코인은 받기 어려움 [추측] → "폭락형" 성격으로 보완
- 진행 순서: 대표 코인 10개로 시범 수집 → 같은 스크립트로 전체 수집
- 요구사항: 요청 횟수 제한 준수, 나눠 받기, 끊겨도 이어서 받기

| 예상 규모 | 값 |
|---|---|
| 코인 수 | 200개 안팎 **[추측]** |
| 코인당 캔들 수 | 최대 약 7~8만 개 (2017년부터) **[추측]** |
| 요청 1회당 캔들 수 | 200개 **[추측]** |
| 수집 시간 | 1~3시간 **[추측]** |
| 용량 | CSV 기준 수백 MB~1GB **[추측]** |

### 통계 추출 (Python: pandas, numpy)
- 수익률 분포, 변동성
- 상승·하락·횡보 구간 나누기, 상태 전환 확률, 상태별 지속 기간
- 급등락 빈도와 크기
- 급등락 전파: 한 코인이 급등락할 때 같은 시간대와 1~3시간 뒤에 다른 코인이 얼마나 따라 움직이는지 **[추측: 데이터로 구분이 될지는 분석해 봐야 앎]**
- 시장 대비 코인별 민감도(β), 코인 간 상관관계
- 성격 분류 (거래대금과 변동성 기준)
- 결과: `data/stats/*.json`

### 데이터 주의점
- 상장 폐지된 코인은 빠짐 **[추측]** → 살아남은 코인만 보게 되는 생존 편향. "폭락형" 성격을 따로 만들어 보완
- 거래가 적은 코인은 캔들이 빠진 시간대가 있을 수 있음 **[추측]** → 빈 구간 처리, 최소 거래대금 기준 필터
- 최근 상장한 코인은 기간이 짧음 → 최소 기간 기준 (예: 6개월 이상)
- 시가총액과 섹터 정보는 업비트 API에 없을 수 있음 **[추측]** → 필요하면 CoinGecko 같은 외부 API 사용
- 업비트 이용약관상 통계를 공개 배포할 수 없으면 → 다른 API나 해외 거래소 시세로 수집 대상을 바꾼다 (그 API의 약관도 먼저 확인). 수익률은 통화 단위와 무관하므로 통계 방식은 그대로 쓰고, 게임 안 가격은 원화로 표시한다. 출처가 바뀌어도 `data/raw/` 형식(시각, 시가, 고가, 저가, 종가, 거래량, 거래대금)은 유지한다

## 부록: 서버 방식 (다음 프로젝트 참고용)

이번 프로젝트는 브라우저에서 시세를 생성하지만, 다음 프로젝트에서는 서버에서 생성해 스트리밍하는 방식으로 확장할 수 있다.

### 구조
- 서버가 게임 세션, 시드, 게임 시계, 미래 데이터를 모두 가지고 있다.
- 다음 캔들을 WebSocket으로 하나씩 보내고, 주문도 서버가 현재가로 체결한다.
- 브라우저는 받은 데이터만 그리므로 미래 시세를 볼 수 없고 조작도 불가능하다. 랭킹이나 대결 기능을 붙이기에 적합하다.

### 도구 후보
| 역할 | 후보 |
|---|---|
| 런타임 | Node.js + TypeScript (생성 엔진 재사용) |
